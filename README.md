# Vacation-Settings-WebSite

Сотрудники выбирают желаемые даты отпуска (до 3 частей), директор смотрит отчёт и выгружает его в Excel.
Лимиты дней по должностям и месяцам ограничивают, сколько людей одной должности может уйти в отпуск одновременно.

**Возможности администратора:** настройка лимитов по месяцам (*Настройки*), максимума дней по должностям
(*Должности*), загрузка списка сотрудников из Excel (*Сотрудники*), ввод отпуска сотруднику без ограничений
(*Ввод отпуска*), отчёт и выгрузка в Excel (*Отчёт*).

Стек: PHP 8.2+ (Eloquent / `illuminate/database`), PostgreSQL, PhpSpreadsheet.

## Быстрый старт (Docker)

Нужны Docker и Docker Compose.

```bash
cp .env.example .env          # необязательно: без него используются значения по умолчанию
docker compose up -d --build
```

Сайт: <http://localhost:8080>

| Что | Где |
|---|---|
| Вход сотрудника (поиск по ФИО) | <http://localhost:8080/sign.php> |
| Админка | <http://localhost:8080/login.php> — демо-вход **admin / admin** |
| Adminer (веб-интерфейс к БД) | `docker compose --profile tools up -d` → <http://localhost:8081> (сервер `db`) |
| PostgreSQL с хоста | `localhost:5433` (пользователь/пароль/БД из `.env`, по умолчанию `vacation`) |

Список из 18 должностей с максимумом дней (`maxday`) входит в схему (`db/schema.sql`) и является рабочим.
Демо-данные (`db/seed_demo.sql`) — 10 выдуманных сотрудников (в том числе ФИО из 4 слов, двойная фамилия и тёзки
с разными должностями), лимиты по месяцам и админ `admin` / `admin`. Чтобы стартовать с пустой БД без демо-данных, закомментируйте строку с `seed_demo.sql` в
`docker-compose.yml` и создайте администратора:

```bash
docker compose exec app php bin/create-admin.php <логин> <пароль>   # пароль от 8 символов
```

### Полезные команды

```bash
docker compose logs -f app                 # ошибки PHP и запросы (display_errors выключен, всё идёт в лог)
docker compose exec app php tests/smoke.php # автотест логики (96 проверок, данные откатываются)
docker compose exec app php bin/check-consistency.php   # проверка целостности данных (ничего не меняет)
docker compose down -v && docker compose up -d   # полностью пересоздать БД (schema.sql + seed заново)
docker compose exec db psql -U vacation vacation # консоль PostgreSQL
```

> SQL-скрипты из `db/` выполняются **один раз** при создании пустого тома БД. Если меняете `schema.sql`, пересоздайте том (`down -v`).

## База данных

`db/schema.sql` **восстановлена по коду приложения**, а не выгружена из боевой БД. Чем надёжно, а чем нет:

**Точно (следует из кода):** названия таблиц и колонок, первичные ключи (из моделей), смысл полей.
Колонки в смешанном регистре (`"janEmp"`, `"isReady"`) создаются в кавычках — Eloquent обращается к ним именно так.

**Предположения** (если боевая БД отличается — приоритет у неё):
- Все числовые поля — `integer NOT NULL DEFAULT 0`. Это требуется коду: сотрудник создаётся только с ФИО и должностью, а `ready.php` сравнивает `lenght1 === 0` строго.
- `isReady` — `boolean NOT NULL DEFAULT false`, `comment` — `text NULL`.
- Внешних ключей нет; допустимость должностей проверяет приложение.
- `users.role`: значение `admin` даёт доступ в админку.
- `params.year`: строка `id = 1` обязательна; в `schema.sql` создаётся со **следующим календарным годом** — поменяйте в админке (Настройки → Год).

Если у вас есть боевая БД, сверьте: `pg_dump --schema-only -U <user> <db>` и сравните с `db/schema.sql`.

### Что добавлено в схему в этой версии

| Таблица | Изменение |
|---|---|
| `positions` | фиксированный список из 18 должностей с `maxday` (добавлять новые нельзя) |
| `cur_emp` | теперь `id`, `fio`, `position` (было только `fio`); заменяется целиком при загрузке Excel |
| `employees` | `fio` — полное ФИО как в файле (любое число слов); `admin1`, `admin2`, `admin3` — часть введена администратором |

`employees.fam / name / otch` остаются: `fam` — первое слово ФИО, `name` — второе, `otch` — все остальные (может быть пустым).

### Миграция боевой БД

Только для **существующей** БД (на новой всё уже есть в `schema.sql`):

```bash
pg_dump -Fc <db> > backup.dump                     # 1. бэкап
psql -U <user> -d <db> -v ON_ERROR_STOP=1 \
     -f db/migrations/001_fixed_positions_admin_vacations.sql   # 2. миграция (можно запускать повторно)
```

Миграция: обновляет `maxday` у должностей по списку и добавляет недостающие (**лимиты по месяцам и счётчики не трогаются**);
добавляет колонки в `employees`; старую `cur_emp` сохраняет как `cur_emp_old` и создаёт новую. Должности, которых нет в списке,
не удаляются — их перечень выводится в конце. После миграции загрузите список сотрудников из Excel (*Сотрудники*).

### Миграция 002: запрет дублей сотрудников

Раньше двойной клик на «Войти» или вход с двух устройств мог создать **две записи одного человека**. Теперь запись создаётся под блокировкой,
а уникальный индекс `(fam, name, otch, position)` не даёт дублей на уровне БД. Для существующей БД:

```bash
psql -U <user> -d <db> -v ON_ERROR_STOP=1 -f db/migrations/002_unique_employees.sql
```
Если дубли уже есть (например, с прошлого запуска), скрипт **остановится, ничего не изменив**, и скажет, сколько их. Запрос для просмотра дублей
и рекомендации по очистке — в шапке `db/migrations/002_unique_employees.sql`.

## Параллельная работа и целостность данных

Выбор дней, сброс, подтверждение, ввод администратором, удаление и очистка выполняются в **транзакциях с блокировкой строк**
(порядок блокировок везде один: сотрудник → должность, поэтому взаимных блокировок нет). Что проверено и исправлено:

| Ситуация | Защита |
|---|---|
| Двое берут «последний» слот месяца | блокировка строки должности при проверке остатка |
| Двойной вход одного человека | консультативная блокировка + уникальный индекс (миграция 002) |
| «Сохранить» одновременно со сбросом части | проверка суммы и запись подтверждения под одной блокировкой |
| «Очистить БД» во время работы сотрудников | одна транзакция с блокировкой `employees`; `DELETE` вместо `TRUNCATE` (id не переиспользуются) |
| Две загрузки списка сотрудников одновременно | блокировка таблицы списка на время замены |

**Проверка целостности** — `php bin/check-consistency.php` сверяет счётчики занятых дней с пересчётом по записям сотрудников, ищет дубли,
отрицательные значения и некорректные части. Ничего не меняет и не блокирует работу. `--fix` исправляет только счётчики.
Рекомендуется запускать после первого часа работы сотрудников и затем раз в день, а также после любого сбоя.

**Стенд гонок** — `tests/race/run.php` запускает несколько процессов одновременно и проверяет инварианты (дубли, слот, подтверждение,
очистка, загрузка списка, общая нагрузка). Он **удаляет данные**, поэтому работает только на отдельной БД, в названии которой есть `race` или `test`:

```bash
docker compose exec db createdb -U vacation vacation_race
docker compose exec db psql -U vacation -d vacation_race -f /docker-entrypoint-initdb.d/01-schema.sql
docker compose exec -e RACE_TESTS=yes -e DB_DATABASE=vacation_race app php tests/race/run.php
```

**Смена года отпусков (Настройки → Год).** Счётчики занятых дней считаются по календарю года (високосный февраль). Если сменить год,
когда в БД уже есть отпуска, счётчики для частей, захватывающих февраль, могут разойтись на 1 день. Меняйте год **после «Очистить БД»**
(а при сомнениях запустите `bin/check-consistency.php`).

## Список сотрудников из Excel

*Сотрудники* → загрузка `.xlsx` / `.xls`. Столбец **A** — ФИО (любое число слов), столбец **B** — должность; первая строка может
быть заголовком (если в ней есть «Должность», столбцы определяются по заголовкам). Загрузка **полностью заменяет** список
(введённые отпуска не удаляются). Файл отклоняется **целиком**, если хотя бы в одной строке должность не из списка, не указано ФИО
или должность, либо строка повторяется — с указанием номеров строк. Должность сравнивается без учёта регистра и лишних пробелов,
но знаки препинания должны совпадать (например, `Фельдшер психиатр.` — с точкой).

## Ввод отпуска администратором

*Ввод отпуска* → выбрать сотрудника → для каждой из трёх частей указать дату начала и число дней.
- Не действуют **никакие** ограничения: лимиты по месяцам, `maxday`, длина части (14–30), пересечения, подтверждённость.
- Дни такой части **не входят** в счётчики занятых дней должности — поэтому при сбросе части и удалении сотрудника они не вычитаются.
- Сотрудник не может изменить или сбросить часть администратора; на своей странице он видит янтарную пометку.
- **Автоподтверждение.** Если после действия админа у сотрудника есть части админа и выбрано дней **не меньше `maxday`** — отпуск подтверждается
  автоматически. Если меньше — остаётся неподтверждённым (то есть «не заполнено») и сотрудник может дозаполнить его сам.
  Если частей админа не осталось (например, после сброса) и выбрано меньше `maxday` — подтверждение снимается;
  если своих дней достаточно — подтверждение не трогается.
- В Excel-выгрузке у каждой части есть столбец «Пометка» (`Введено администратором`), а ячейки такой части залиты цветом; то же в отчёте.

## Контроль заполнения

Отпуск считается **не заполненным до конца**, если выбрано **меньше дней, чем `maxday`** должности **или** он **не подтверждён**
сотрудником (не нажато «Сохранить»). Правило одинаково для всех, включая отпуска, введённые администратором
(но при вводе админом действует автоподтверждение: выбрано не меньше `maxday` — отпуск считается подтверждённым).

- **Отчёт → выпадающее меню:** «Не приступили к заполнению (N)» — сотрудники из списка, у которых нет записи или не выбрано ни одного дня;
  «Заполнили не до конца (N)» — выбрана хотя бы одна часть, но отпуск не заполнен до конца. Группы не пересекаются.
  В списках карточка имеет цветную полоску слева (розовая — не заполнено, зелёная — заполнено) и полосу статуса с причиной
  («Не заполнено — Выбрано 18 из 20 дн. · не подтверждён»).
- **Поиск по ФИО в отчёте** — такое же поле с подсказками, как на входе: выбор из списка открывает этого сотрудника
  (в том числе не приступившего; тёзки различаются должностью), а обычный ввод + Enter/лупа по-прежнему фильтрует по части ФИО.
- **Excel:** столбец «Статус заполнения», у незаполненных розовые ФИО, должность и статус; они идут в **конце таблицы**
  (внутри группы — по должности и фамилии). Сотрудники без записи (ни разу не заходили) в таблицу **не попадают**,
  но видны на сайте.

## Запуск без Docker

PHP 8.2+ с расширениями `pdo_pgsql`, `gd`, `zip`, `mbstring`, `xml`; PostgreSQL 12+; Composer.

```bash
composer install --no-dev
cp .env.example .env            # задайте параметры БД
psql -U <user> -d <db> -f db/schema.sql     # схема + 18 должностей
php bin/create-admin.php <логин> <пароль>
```

`.env` необязателен: если его нет, значения берутся из переменных окружения.

**На боевом сервере закройте от веб-доступа** `vendor/`, `db/`, `tests/`, `bin/`, `models/`, `.env`, `.git/`, `composer.*`,
`*.sql` — образец правил для Apache в `docker/apache-security.conf`. Для nginx нужны аналогичные `location`-правила.

## Что изменено относительно исходной версии

Правки сделаны отдельными коммитами (`git log`). Правила выбора дат сотрудником (длина частей, лимиты по месяцам, `maxday`) не менялись — новые возможности перечислены в пунктах 5–8.

1. **Баги и экранирование.** Сброс комментария больше не «освобождает» дни части 3 (счётчики занятых дней уменьшались, хотя отпуск оставался); экранирование комментария, ФИО и должности (XSS); проверки на несуществующего сотрудника.
2. **Безопасность.** Удалён `cancel.php` (был доступен без авторизации и менял данные, не корректируя счётчики); удаление сотрудника в отчёте — POST вместо GET-ссылки; текст ошибки БД не показывается пользователю; `sign.php` принимает только ФИО из `cur_emp` и должности из `positions`.
3. **Транзакция и запрет пересечений.** Выбор дней выполняется в транзакции с блокировкой строки должности: на тесте из 6 параллельных запросов старый код пере­бронировал слот в 27 из 30 попыток, новый — в 0. Части отпуска одного сотрудника не могут пересекаться (вплотную друг к другу — можно). Дубли из `user.php` (3 копии по ~100 строк) заменены одной функцией `handlePartRequest`.
4. **Docker, схема БД, README, `bin/create-admin.php`.**
5. **Фиксированные должности.** 18 должностей с `maxday` в схеме; страница *Должности* — менять можно только `maxday`.
6. **Список сотрудников из Excel** (*Сотрудники*) с жёсткой проверкой должностей и номерами строк.
7. **Вход по поиску ФИО.** Должность подставляется из списка, ФИО — любое число слов, без проверки «ровно 3 слова».
8. **Ввод отпуска администратором** без ограничений, с пометкой и цветом в отчёте и Excel (по каждой части).
9. **Контроль заполнения:** пометка «не заполнено до конца» на сайте и в Excel, группы «Не приступили» / «Заполнили не до конца» в отчёте.
10. **Гонки данных:** исправлены дубли при двойном входе, подтверждение против сброса, очистка БД под нагрузкой, одновременная загрузка списка;
    добавлены проверка целостности и стенд гонок (см. выше).

Логика выбора дат проверена на 19 сценариях (границы длины, переход через месяц и год, нехватка дней, лимит `maxday`, сброс, подтверждение) — результаты нового кода совпадают с прежним побайтно (кроме намеренных изменений выше).
