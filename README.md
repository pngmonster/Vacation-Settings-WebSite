# Vacation Settings

Веб-приложение для планирования отпусков в коллективе. Сотрудники сами выбирают даты отпуска в рамках установленных
лимитов, администратор (например, директор) видит общую картину, контролирует, кто заполнил отпуск, вводит отпуска
вручную и выгружает итог в Excel. Рассчитано на рабочую группу в сотни человек и одного администратора.

## Возможности

**Для сотрудника**

- Вход без пароля: поиск своего ФИО в списке (подсказки при вводе, работает на телефоне); должность подставляется из списка.
- Выбор до трёх частей отпуска (месяц, число, количество дней) с проверкой правил и лимитов; комментарий.
- Подтверждение отпуска кнопкой «Сохранить»; после этого отпуск доступен только для просмотра.

**Для администратора**

- **Настройки:** год отпусков и лимиты занятых дней по месяцам для каждой должности.
- **Должности:** фиксированный список; можно менять максимум дней отпуска.
- **Сотрудники:** загрузка списка сотрудников из Excel с жёсткой проверкой (ошибки с номерами строк).
- **Ввод отпуска:** постановка отпуска сотруднику без ограничений; такие части помечаются в отчётах и в Excel.
- **Отчёт:** карточки сотрудников со статусом заполнения, фильтры «Не приступили» и «Заполнили не до конца», поиск по ФИО,
  быстрый переход к редактированию, удаление, выгрузка в Excel с цветовой разметкой.
- **Очистка БД** перед новым сезоном: полная пересборка базы, как при первой установке (сохраняется только учётная запись администратора).

## Правила отпуска

- Часть 1 — не короче 14 дней; части 2 и 3 — от 1 дня. Максимальная длина одной части: 30 дней, если максимум дней по должности
  (`maxday`) не меньше 48, иначе 21.
- Начало части — число с 1 по 20 выбранного месяца; части одного сотрудника не пересекаются.
- Сумма дней всех частей не больше `maxday`; в каждом месяце суммарно занято не больше лимита по должности.
- Сотрудник подтверждает отпуск, когда выбрано ровно `maxday` дней.
- Администратор вводит отпуск **без ограничений**; дни таких частей не учитываются в лимитах. Если после ввода выбрано не меньше
  `maxday`, отпуск подтверждается автоматически.
- Отпуск считается **не заполненным до конца**, если выбрано меньше `maxday` дней или он не подтверждён.

## Технологии

PHP 8.2+ (без фреймворка, Eloquent ORM), PostgreSQL 12+, Apache, PhpSpreadsheet (Excel), Docker и Docker Compose,
Caddy (HTTPS на боевом сервере). Фронтенд — серверные шаблоны PHP, обычный JavaScript без сборки.

## Быстрый старт (локально, Docker)

```bash
git clone <адрес-репозитория> vacation && cd vacation
cp .env.example .env                  # необязательно: есть значения по умолчанию
docker compose up -d --build
```

| Что | Адрес |
|---|---|
| Вход сотрудника | <http://localhost:8080/sign.php> |
| Админка | <http://localhost:8080/login.php> — демо-вход `admin` / `admin` (только в режиме `APP_ENV=dev`, который включён в этом compose-файле) |
| Adminer (веб-интерфейс БД) | `docker compose --profile tools up -d`, затем <http://localhost:8081> |

Локальный стек создаёт БД со схемой и демо-данными (`db/seed_demo.sql`: выдуманные сотрудники, лимиты, демо-администратор).
Чтобы пересоздать БД с нуля: `docker compose down -v && docker compose up -d --build`.

Полезные команды:

```bash
docker compose logs -f app                              # логи приложения
docker compose exec app php tests/smoke.php             # автотест логики
docker compose exec app php bin/check-consistency.php   # проверка целостности данных
docker compose exec db psql -U vacation vacation        # консоль PostgreSQL
```

Запуск без Docker: PHP 8.2+ с расширениями `pdo_pgsql`, `gd`, `zip`, `mbstring`, `xml`; PostgreSQL; Composer.
`composer install`, `cp .env.example .env`, примените `db/schema.sql`, создайте администратора `php bin/create-admin.php <логин> <пароль>`.

## Конфигурация

Настройки берутся из переменных окружения, а при отсутствии — из файла `.env`. Реальное окружение приоритетнее `.env`.

| Переменная | Назначение |
|---|---|
| `DB_*` | Подключение к PostgreSQL (`DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`) |
| `APP_ENV` | `production` (по умолчанию) или `dev`; режим `dev` ослабляет защиту и предназначен только для локальных тестов |
| `APP_TRUST_PROXY` | `1`, если приложение стоит за обратным прокси (HTTPS) |
| `ADMIN_IDLE_MINUTES`, `ADMIN_SESSION_HOURS` | Тайм-аут бездействия и предельная длительность входа администратора |
| `DOMAIN`, `ACME_EMAIL`, `COMPOSE_FILE` | Только для боевого сервера, см. [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) |

Полный пример — `.env.example`.

## Тестирование

| Что | Команда |
|---|---|
| Логика отпусков, счётчики, пароли, ввод администратором | `php tests/smoke.php` (нужна БД; данные откатываются) |
| Поле поиска ФИО | `npm i jsdom && node tests/js/fio-combobox.test.js` |
| Целостность данных | `php bin/check-consistency.php` |
| Гонки данных (параллельные процессы) | `RACE_TESTS=yes DB_DATABASE=<имя_с_race_или_test> php tests/race/run.php` |
| Защита входа на запущенном сайте | `php tests/security/http-check.php --base=<url> --user=<логин> --pass=<пароль>` |

Стенд гонок **удаляет данные** и отказывается работать на БД без `race` или `test` в названии. Подробности — в
[docs/DATABASE.md](docs/DATABASE.md) и [docs/SECURITY.md](docs/SECURITY.md).

## Безопасность

Защита админки: блокировка перебора пароля, CSRF-токены, строгие cookie, тайм-аут сессии, заголовки безопасности, политика
паролей, вход только по HTTPS в боевом режиме. Страницы сотрудников паролем не защищены по замыслу проекта. Подробнее —
[docs/SECURITY.md](docs/SECURITY.md).

## Развёртывание

Боевой сервер — Docker Compose: приложение, PostgreSQL и Caddy с автоматическим HTTPS (Let's Encrypt); резервные копии и
обновление скриптами. Пошаговая инструкция — [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Разработка

- Новая страница админки: `require_once 'auth.php';` в начале файла (проверка входа и CSRF включается автоматически),
  `<?= csrfField() ?>` в каждой POST-форме, `esc()` для всего вывода.
- Изменения данных, затрагивающие счётчики, выполняйте в транзакции с блокировкой в порядке «сотрудник → должность».
- Изменение схемы — новый файл `db/migrations/NNN_*.sql` и запись о нём в `db/schema.sql` (см. [docs/DATABASE.md](docs/DATABASE.md)).
- Перед коммитом запускайте `php tests/smoke.php` и проверяйте синтаксис: `php -l <файл>`.
