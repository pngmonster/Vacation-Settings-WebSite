# Vacation-Settings-WebSite

Сотрудники выбирают желаемые даты отпуска (до 3 частей), директор смотрит отчёт и выгружает его в Excel.
Лимиты дней по должностям и месяцам ограничивают, сколько людей одной должности может уйти в отпуск одновременно.

Стек: PHP 8.2+ (Eloquent / `illuminate/database`), PostgreSQL, PhpSpreadsheet.

## Быстрый старт (Docker)

Нужны Docker и Docker Compose.

```bash
cp .env.example .env          # необязательно: без него используются значения по умолчанию
docker compose up -d --build
```

Сайт: <http://localhost:8080>

| Что | Где |
|---|---|
| Вход сотрудника | <http://localhost:8080/sign.php> |
| Админка | <http://localhost:8080/login.php> — демо-вход **admin / admin** |
| Adminer (веб-интерфейс к БД) | `docker compose --profile tools up -d` → <http://localhost:8081> (сервер `db`) |
| PostgreSQL с хоста | `localhost:5433` (пользователь/пароль/БД из `.env`, по умолчанию `vacation`) |

В демо-данных 3 должности и 6 сотрудников (`Иванов Иван Иванович`, `Петрова Мария Сергеевна`, …), все значения выдуманы —
см. `db/seed_demo.sql`. Чтобы стартовать с пустой БД без демо-данных, закомментируйте строку с `seed_demo.sql` в
`docker-compose.yml` и создайте администратора:

```bash
docker compose exec app php bin/create-admin.php <логин> <пароль>   # пароль от 8 символов
```

### Полезные команды

```bash
docker compose logs -f app                 # ошибки PHP и запросы (display_errors выключен, всё идёт в лог)
docker compose exec app php tests/smoke.php # автотест логики отпусков (данные откатываются)
docker compose down -v && docker compose up -d   # полностью пересоздать БД (schema.sql + seed заново)
docker compose exec db psql -U vacation vacation # консоль PostgreSQL
```

> SQL-скрипты из `db/` выполняются **один раз** при создании пустого тома БД. Если меняете `schema.sql`, пересоздайте том (`down -v`).

## База данных

`db/schema.sql` **восстановлена по коду приложения**, а не выгружена из боевой БД. Чем надёжно, а чем нет:

**Точно (следует из кода):** названия таблиц и колонок, первичные ключи (из моделей), смысл полей.
Колонки в смешанном регистре (`"janEmp"`, `"isReady"`) создаются в кавычках — Eloquent обращается к ним именно так.

**Предположения** (если боевая БД отличается — приоритет у неё):
- Все числовые поля — `integer NOT NULL DEFAULT 0`. Это требуется коду: `sign.php` создаёт сотрудника только с ФИО и должностью, а `ready.php` сравнивает `lenght1 === 0` строго.
- `isReady` — `boolean NOT NULL DEFAULT false`, `comment` — `text NULL`.
- Внешних ключей и уникальных индексов нет (в коде `employees` ищется по ФИО + должности через `first()`; уникальный индекс есть в `schema.sql` закомментированным).
- `users.role`: значение `admin` даёт доступ в админку (по `login.php`); других ролей в коде нет.
- `params.year`: строка `id = 1` обязательна. В `schema.sql` она создаётся со **следующим календарным годом** — это предположение, поменяйте в админке (Настройки → Год).

Если у вас есть боевая БД, сверьте: `pg_dump --schema-only -U <user> <db>` и сравните с `db/schema.sql`.

## Запуск без Docker

PHP 8.2+ с расширениями `pdo_pgsql`, `gd`, `zip`, `mbstring`, `xml`; PostgreSQL 12+; Composer.

```bash
composer install --no-dev
cp .env.example .env            # задайте параметры БД
psql -U <user> -d <db> -f db/schema.sql
php bin/create-admin.php <логин> <пароль>
```

`.env` необязателен: если его нет, значения берутся из переменных окружения.

**На боевом сервере закройте от веб-доступа** `vendor/`, `db/`, `tests/`, `bin/`, `models/`, `.env`, `.git/`, `composer.*`,
`*.sql` — образец правил для Apache в `docker/apache-security.conf`. Для nginx нужны аналогичные `location`-правила.

## Что изменено относительно исходной версии

Правки сделаны отдельными коммитами (`git log`), бизнес-правила не менялись.

1. **Баги и экранирование.** Сброс комментария больше не «освобождает» дни части 3 (счётчики занятых дней уменьшались, хотя отпуск оставался); экранирование комментария, ФИО и должности (XSS); проверки на несуществующего сотрудника.
2. **Безопасность.** Удалён `cancel.php` (был доступен без авторизации и менял данные, не корректируя счётчики); удаление сотрудника в отчёте — POST вместо GET-ссылки; текст ошибки БД не показывается пользователю; `sign.php` принимает только ФИО из `cur_emp` и должности из `positions`.
3. **Транзакция и запрет пересечений.** Выбор дней выполняется в транзакции с блокировкой строки должности: на тесте из 6 параллельных запросов старый код пере­бронировал слот в 27 из 30 попыток, новый — в 0. Части отпуска одного сотрудника не могут пересекаться (вплотную друг к другу — можно). Дубли из `user.php` (3 копии по ~100 строк) заменены одной функцией `handlePartRequest`.
4. **Docker, схема БД, README, `bin/create-admin.php`.**

Логика выбора дат проверена на 19 сценариях (границы длины, переход через месяц и год, нехватка дней, лимит `maxday`, сброс, подтверждение) — результаты нового кода совпадают с прежним побайтно (кроме намеренных изменений выше).
