# Безопасность

Документ описывает модель защиты. Администратор один, сайт открыт в интернете, в базе персональные данные сотрудников,
поэтому защищена в первую очередь **админка**. Страницы сотрудников (вход по ФИО, выбор отпуска) паролем не защищены по
замыслу проекта: сотрудник выбирает своё ФИО из списка. Это следует учитывать при оценке рисков.

## Защита входа администратора

| Угроза | Защита |
|---|---|
| Подбор пароля | После 5 неудач с одного IP на один логин вход блокируется на 15 минут; не более 20 неудач с одного IP на любые логины. Блокируется **атакующий адрес, а не логин**: администратор с другого адреса входит спокойно |
| Определение существующего логина по скорости ответа | Время ответа одинаково для существующего и несуществующего логина |
| Слабый пароль | В `production` вход разрешён только с паролем от 12 символов, не равным логину и не из популярных. `bin/create-admin.php` не создаёт слабых паролей. Демо-пароль в боевом режиме не работает |
| Подделка запроса с чужого сайта (CSRF) | Токен во всех админских формах и действиях (удаление, очистка, загрузка списка, ввод отпуска, выход, выгрузка Excel) плюс `SameSite=Lax`. Проверка встроена в `auth.php`: новая страница админки защищена автоматически |
| Кража сессии | cookie `HttpOnly`, `Secure` (по HTTPS), `SameSite=Lax`; строгий режим сессий; идентификатор меняется при входе; выход уничтожает сессию на сервере |
| Забытая открытая сессия | Автовыход через 30 минут бездействия и в любом случае через 8 часов |
| Пароль по открытому http | В `production` вход по http запрещён |
| Встраивание в чужую страницу (кликджекинг) | `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'` |
| Прочее | `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS (по HTTPS); версия PHP и сервера не раскрывается; админские страницы не кэшируются (после выхода «Назад» ничего не покажет) |
| Выброс админа из системы чужой страницей | Анонимные запросы не создают сессию и не ставят cookie; форма входа защищена отдельной cookie («двойная отправка») |

Журнал попыток входа: таблица `login_attempts`, просмотр — `php bin/admin-security.php logins`. Снять блокировку —
`php bin/admin-security.php unlock`.

## Настройки

| Переменная | Значение |
|---|---|
| `APP_ENV` | `production` (по умолчанию, если не задано) — строгие правила. `dev` — только для локальных тестов (http и слабые пароли разрешены); в этом режиме на всех страницах админки показывается красный баннер «РЕЖИМ РАЗРАБОТКИ» |
| `APP_TRUST_PROXY` | `1`, если приложение стоит за обратным прокси, который передаёт `X-Forwarded-Proto` и `X-Forwarded-For`. Берётся **последний** адрес из `X-Forwarded-For` (его добавил ваш прокси). Включайте только если приложение недоступно в обход прокси |
| `ADMIN_IDLE_MINUTES`, `ADMIN_SESSION_HOURS` | тайм-аут бездействия (30) и предельная длительность входа (8) |

Реальные переменные окружения всегда приоритетнее файла `.env`. В `docker-compose.prod.yml` `APP_ENV=production` и
`APP_TRUST_PROXY=1` заданы жёстко.

## Обратный прокси

Приложение должно быть доступно **только** через ваш прокси. Прокси обязан передавать `X-Forwarded-Proto: https` и
`X-Forwarded-For` с настоящим адресом клиента (заголовок клиента должен перезаписываться). Caddy из `deploy/Caddyfile` делает это сам.
Пример для nginx:

```nginx
location / {
    proxy_pass http://app:80;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;   # перезаписывает, а не дополняет заголовок клиента
}
```

Если перед вашим прокси стоит ещё один (например, CDN), настройте внутренний так, чтобы `X-Forwarded-For` содержал реальный адрес
клиента, иначе ограничения по IP будут применяться к адресу CDN.

## Проверка защиты на работающем сайте

```bash
php tests/security/http-check.php --base=https://<домен> --user=<логин> --pass='<пароль>' --expect-production --check-demo
```

Проверяет заголовки, cookie, закрытость админских страниц, CSRF на всех действиях, выход, фиксацию сессии, режим работы и
отсутствие демо-входа. Флаг `--bruteforce` дополнительно проверяет блокировку перебора (блокирует IP проверяющего на 15 минут;
снять: `php bin/admin-security.php unlock`). Скрипт не меняет данные.

## Разработчикам

- Каждая админская страница начинается с `require_once 'auth.php';` — это включает проверку входа, тайм-аутов и CSRF.
- В каждую POST-форму админки добавляйте `<?= csrfField() ?>`; для запросов из JavaScript передавайте токен полем `csrf_token`
  или заголовком `X-CSRF-Token` (значение — `csrfToken()`).
- Весь вывод в HTML экранируйте функцией `esc()`.
- Не меняйте порядок чтения настроек в `envValue()`: реальное окружение должно быть приоритетнее `.env`.
