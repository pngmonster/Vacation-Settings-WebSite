# База данных

PostgreSQL 12+. Схема новой установки — `db/schema.sql` (создаёт таблицы, список должностей, строку параметров и таблицу учёта
миграций). Доступ из PHP — Eloquent (`illuminate/database`), модели в `models/`.

## Таблицы

| Таблица | Назначение |
|---|---|
| `positions` | **Фиксированный** список должностей. `maxday` — сколько дней отпуска положено; `jan..dec` — лимиты занятых дней по месяцам; `janEmp..decEmp` — уже занятые дни (счётчики) |
| `cur_emp` | Список сотрудников (ФИО + должность), загружается из Excel и заменяется целиком. Используется на странице входа |
| `employees` | Записи отпусков сотрудников. Три части: `monN` (месяц), `dayN` (число), `lenghtN` (дней), `adminN` (часть введена администратором); `isReady` — подтверждён; `fio` — полное ФИО (любое число слов); `comment` |
| `params` | Параметры; строка `id = 1` содержит год отпусков |
| `users` | Администраторы (`password_hash`, `role = admin`) |
| `login_attempts` | Журнал попыток входа администратора (защита от перебора) |
| `schema_migrations` | Какие миграции уже применены |

Особенности, о которых нужно помнить:

- Колонки смешанного регистра (`"janEmp"`, `"isReady"`) создаются в кавычках: так к ним обращается Eloquent.
- Название колонки `lenght` (с опечаткой) — часть схемы, менять нельзя.
- `employees.fam / name / otch` — ФИО по словам в нижнем регистре: `fam` — первое слово, `name` — второе, `otch` — все остальные.
  Уникален ключ `(fam, name, otch, position)`.
- Дни частей, введённых администратором, **не входят** в счётчики `janEmp..decEmp`.

## Миграции

Файлы `db/migrations/NNN_*.sql` применяются по порядку, каждый один раз. Применение и учёт — `bin/migrate.php`:

```bash
php bin/migrate.php            # применить новые миграции
php bin/migrate.php --status   # что применено, что ожидает
php bin/migrate.php --baseline # отметить текущие миграции применёнными, не выполняя (для БД, где они уже сделаны вручную)
```

Новая БД из `db/schema.sql` уже содержит все миграции (схема сама записывает их в `schema_migrations`).
**Добавляя миграцию, добавьте её имя в `INSERT INTO schema_migrations` в `db/schema.sql`.**
Миграции пишите так, чтобы они были атомарными (`BEGIN … COMMIT` или один блок `DO`).

## Параллельная работа

Выбор дней, сброс, подтверждение, ввод администратором, удаление и очистка выполняются в транзакциях с блокировкой строк.
Порядок блокировок везде один: **сотрудник → должность**, поэтому взаимных блокировок нет.

| Ситуация | Защита |
|---|---|
| Двое берут «последний» слот месяца | блокировка строки должности при проверке остатка |
| Двойной вход одного человека | консультативная блокировка + уникальный индекс `employees_person_uniq` |
| «Сохранить» одновременно со сбросом части | проверка суммы и запись подтверждения под одной блокировкой |
| «Очистить БД» во время работы сотрудников | одна транзакция; запросы сотрудников дожидаются завершения пересборки и не получают ошибок |
| Две загрузки списка сотрудников одновременно | блокировка таблицы списка на время замены |

## Очистка БД

Кнопка «Очистить БД» в админке **заново собирает базу**: таблицы `employees`, `cur_emp`, `positions`, `params` удаляются и создаются
из `db/schema.sql`, то есть ровно так же, как при первой установке. После неё:

- нет ни сотрудников, ни их отпусков, ни списка сотрудников из Excel;
- лимиты по месяцам и счётчики занятых дней равны нулю;
- максимум дней (`maxday`) по должностям и год отпусков вернулись к значениям по умолчанию из схемы;
- нумерация `id` начинается с единицы.

Не затрагиваются `users` (учётная запись администратора, повторный вход не нужен), `login_attempts` и `schema_migrations`.
Пересборка выполняется одной транзакцией (DDL в PostgreSQL транзакционный): при любой ошибке данные остаются как были.
Функция — `rebuildDatabase()` в `functions.php`; тесты — сценарий `rebuild` стенда гонок.

> Так как нумерация `id` начинается заново, открытые у сотрудников **старые страницы** (с прежними `id`) после пересборки могут
> указывать на других людей. Выполняйте пересборку, когда сотрудники не работают с сайтом.

## Проверка целостности

```bash
php bin/check-consistency.php          # только проверка, ничего не меняет и не блокирует
php bin/check-consistency.php --fix    # пересчитать и исправить счётчики занятых дней
```

Сверяет счётчики с пересчётом по записям сотрудников, ищет дубли, отрицательные значения, должности, которых нет в списке,
и некорректные части. Рекомендуется запускать после первого часа работы сотрудников, затем раз в день и после любого сбоя.

## Демо-данные
